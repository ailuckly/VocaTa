# 测试策略

这份文档记录 VocaTa 当前测试现状和后续补测优先级。目标不是追求虚高覆盖率，而是优先保护核心业务、协议边界和容易被 AI 协作误改的模块。

## 当前测试现状

### 后端

- 测试框架：JUnit 5、Spring Boot Test、Mockito。
- 当前已有 Controller、Service、WebSocket、配置类相关测试。
- `mvn test` 当前会执行 Surefire 识别到的 `*Test` 测试类。
- `com.vocata.ai.test` 下的示例类当前更像用法示例，不属于稳定自动化测试主线。

### 用户端

- 测试框架：Vitest、Vue Test Utils、jsdom。
- 当前覆盖 API 参数序列化、页面关键文案、聊天页基础渲染、聊天输入组件、运行时 crypto 兼容，以及头像 fallback 纯函数。

### 管理端

- 当前未配置测试框架。
- 暂不单独引入 Vitest，避免为了形式补齐而增加维护成本。
- 后续若管理端开始承载复杂表单、权限或批量操作，再补测试工具链。

## 缺测试的核心模块

- 后端 AI 流式链路：LLM chunk、句子切分、TTS 编排、错误和取消路径。
- 后端 WebSocket 会话状态：连接鉴权、barge-in、异常清理、重复音频会话。
- 后端角色模块：筛选、标签、创建、AI 生成字段更新、分页边界。
- 用户端 AI 聊天运行时：WebSocket 重连、录音状态、音频队列、VAD、barge-in。
- 用户端页面编排：`ChatPage.vue` 的消息加载、流式消息、滚动和错误恢复。
- 管理端核心表格和登录流程。

## 优先补测顺序

1. 纯函数和数据转换：头像 fallback、消息格式转换、请求参数序列化。
2. 协议边界：WebSocket 消息类型、STT/LLM/TTS 流程事件、错误消息。
3. 核心业务规则：角色筛选、收藏、会话创建、权限边界。
4. UI 行为：聊天输入、搜索筛选、登录、管理端表格操作。
5. E2E：登录、创建角色、进入会话、发送文本消息、基础语音链路 smoke。

## 单元测试

适合单元测试的内容：

- 无副作用纯函数。
- DTO/entity 到 response 的转换。
- 请求参数序列化。
- 字符串、时间、分页、标签、头像 fallback 等边界逻辑。
- service 中可隔离的业务规则。

## 集成测试

适合集成测试的内容：

- Controller API 契约。
- 鉴权和路由保护。
- Service + Mapper 的数据路径。
- WebSocket handler 的会话清理和错误路径。
- 第三方 AI provider 的适配层在 mock WebClient 下的请求/响应契约。

## E2E 测试

暂不立即引入 E2E 工具。后续适合覆盖：

- 用户注册/登录。
- 浏览和筛选角色。
- 创建角色。
- 创建会话并发送文本消息。
- 语音通话入口 smoke test。
- 管理端登录和基础列表操作。

## Mock 策略

- 第三方 LLM/STT/TTS/Qiniu/邮件服务默认 mock，不在常规测试中打真实外部接口。
- WebSocket 测试使用 mock session、mock provider 和可控事件流。
- 前端 API 测试优先 mock Axios 层或具体 API 模块。
- 音频、MediaRecorder、AudioContext、WebSocket 等浏览器能力应在测试 setup 中提供稳定 stub。
- 测试数据应贴近真实 API 契约，但不要包含真实 token、密钥或生产数据。
