## 当前非阻断警告

这些警告不阻塞当前验证通过，但应在后续规范化工作中收口，避免长期变成默认噪音。

| 警告 | 当前影响 | 建议处理 |
| --- | --- | --- |
| 本机 Java 版本为 21，项目基线为 Java 17 | 当前测试可运行，但本地和 CI/runtime 基线不一致 | 日常开发切到 Java 17，或另开任务明确升级 Java baseline |
| 当前 Node 版本高于 `.nvmrc` 推荐版本 | 当前 Node 22.22.3 符合支持范围，但和推荐基线 22.12.0 不完全一致 | 需要复现最小支持环境时执行 `nvm use`；日常开发可继续使用支持范围内的新补丁版本 |
| 本地 `.env` 缺少 Docker 内部连接变量 | 宿主机开发不一定受影响，全量 Docker 模式可能配置不完整 | 从 `.env.example` 同步 `DOCKER_DB_HOST`、`DOCKER_DB_PORT`、`DOCKER_REDIS_HOST`、`DOCKER_REDIS_PORT` |
| 前端 production build 存在 chunk size warning | 不阻塞构建，但说明首包体积需要持续关注 | 单独评估动态导入、manualChunks 或字体加载策略 |

## 当前结论

仓库已经具备规范开源项目的基础协作入口，AI agent 的任务、实现、审查和交付证据也有了
明确流程。但距离成熟开源项目仍差一组需要改变工程行为的能力，尤其是数据库 migration
baseline、依赖/安全自动化、release workflow 硬化和核心链路测试夹具。

这些剩余项会影响数据库、CI、依赖或发布行为，应该按 `docs/开源成熟度路线图.md` 拆成独立
PR 推进。数据库 migration baseline 已有 `docs/adr/0001-database-migration-baseline.md`
和 `docs/数据库迁移基线方案.md` 作为后续执行入口；依赖与安全自动化已有
`docs/adr/0002-dependency-and-security-automation.md` 和 `docs/依赖与安全自动化方案.md`
作为后续执行入口；release workflow 硬化已有 `docs/adr/0003-release-workflow-hardening.md`
和 `docs/发布流程硬化方案.md` 作为后续执行入口；AI 核心链路测试夹具已有
`docs/adr/0004-core-ai-pipeline-test-fixtures.md` 和 `docs/AI核心链路测试夹具方案.md`
作为后续执行入口。
