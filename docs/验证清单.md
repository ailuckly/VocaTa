# 验证清单

以下入口按当前仓库的实际脚本和工作流整理，用于验证当前可执行基线、两个前端构建链路、Docker 编排，以及 staging 部署后的基础可用性。

## 推荐入口

```bash
./scripts/doctor.sh
./scripts/doctor.sh --json
./scripts/check.sh
./scripts/pre-pr-check.sh
./scripts/report-frontend-assets.sh
./scripts/validate-docs.sh
./scripts/validate-backend.sh
./scripts/validate-web.sh
./scripts/validate-admin.sh
./scripts/validate-docker.sh
```

说明：以上脚本只是对当前基线命令做薄封装，不改变实际校验内容。默认本地直接从仓库根目录执行。

`./scripts/doctor.sh` 是只读环境体检入口，用于检查本机是否具备 Java、Maven、Node、npm、
Docker、`.env` 和关键项目文件。它还会比较 `.env` 与 `.env.example` 的变量名是否漂移，
但不会打印任何变量值。加 `--json` 会输出机器可读摘要，包含 `failures`、`warnings`、
`checks` 和 `env_key_drift`。它不替代验证脚本，也不会启动服务或安装依赖。

`./scripts/report-frontend-assets.sh` 是只读的前端 production build asset 体积报告入口。
它读取 `vocata-web/dist` 和 `vocata-admin/dist` 中已有的构建产物，按大小输出前 20 个文件，
并用 `WARN_KB` 标记超过阈值的文件。默认阈值为 500 KiB。它不会自动执行构建；如缺少
`dist`，先运行对应的 `./scripts/validate-web.sh` 或 `./scripts/validate-admin.sh`。

`./scripts/check.sh` 是默认的一键质量检查入口，会依次运行：

- `./scripts/validate-docs.sh`
- `./scripts/validate-backend.sh`
- `./scripts/validate-web.sh`
- `./scripts/validate-admin.sh`

Docker 检查单独保留为 `./scripts/validate-docker.sh`，因为它依赖本机 Docker 环境。

## PR 前范围检查

```bash
./scripts/pre-pr-check.sh
./scripts/pre-pr-check.sh --json
./scripts/pre-pr-check.sh --run
```

说明：`pre-pr-check.sh` 会根据当前分支相对 `origin/develop`、工作区和未跟踪文件的变更范围，
列出 PR 前建议运行的验证命令，并在 `Risk review hints` 中输出风险提示。风险提示覆盖
鉴权/权限、数据库/schema、AI streaming/provider、API 契约、依赖/工具链、Docker/env 和
CI/release 等路径。默认只输出计划；加 `--json` 会输出机器可读 JSON，包含
`recommended_commands`、`risk_review_hints`、`changed_file_sample`、变更区域和风险布尔值；
加 `--run` 会执行推荐命令。`--json` 不能和 `--run` 同时使用。它不会替代人工确认、
PR 描述里的风险说明、人工 review 或 Docker/staging 的环境验证。提交 PR 时，应在
`.github/pull_request_template.md` 的“风险提示处理”中粘贴或概述 `Risk review hints`，
并说明已处理或不适用原因。涉及 `vocata-web`、`vocata-admin` 或验证脚本的变更，会建议在
构建后运行 `./scripts/report-frontend-assets.sh` 查看 production build asset 体积。

## 文档、模板和元数据

```bash
./scripts/validate-docs.sh
```

说明：文档脚本会检查工作区 diff 空白、本仓库文档尾随空格、Markdown 本地链接、
GitHub issue template YAML、前端 `package.json`、后端 `pom.xml`、前端 Node engine 策略一致性、
`.java-version` 是否匹配后端 `pom.xml` 的 Java 基线、`.nvmrc` 是否落在支持的 Node 版本范围内、
`.env.example` 前端 Docker 构建模式与 npm scripts 是否匹配、`scripts/*.sh` 语法、验证入口
可执行位、`.env.example` 是否存在重复变量、`docker-compose.yml` 引用变量是否都在 `.env.example`
中声明、技术债 backlog 契约、pre-PR 风险提示契约、常见密钥模式和 Node 版本策略。只修改文档、模板、说明文件、脚本或开源协作资料时，
优先运行这个脚本。

## 后端当前基线

```bash
./scripts/validate-backend.sh
```

说明：后端脚本依次执行 Maven 打包基线和 smoke test，默认使用 `/tmp/juhao_m2repo` 作为本地 Maven 仓库；如需覆盖，可临时传入 `MAVEN_REPO_LOCAL=/path/to/m2repo`。

## 用户端

```bash
./scripts/validate-web.sh
```

说明：用户端脚本依次执行 ESLint、TypeScript type-check、Vitest 和 production build。
模块内也可以运行 `cd vocata-web && npm run check` 执行同等检查。

## 管理端

```bash
./scripts/validate-admin.sh
```

说明：管理端脚本依次执行 ESLint、TypeScript type-check 和 production build。当前管理端暂未配置测试框架。
模块内也可以运行 `cd vocata-admin && npm run check` 执行同等检查。

## 前端产物体积报告

```bash
./scripts/report-frontend-assets.sh
./scripts/report-frontend-assets.sh web
./scripts/report-frontend-assets.sh admin
./scripts/report-frontend-assets.sh --json
WARN_KB=1024 ./scripts/report-frontend-assets.sh
```

说明：该脚本只读取已有 `dist`，用于把 Vite chunk size warning 和字体、图片等大文件变成可复查的本地报告。
加 `--json` 可输出机器可读 JSON，包含 `target`、`warn_kb` 和每个前端模块的 `largest_assets`。
它当前不作为失败门禁，不改变 Vite 构建配置，也不替代 `validate-web.sh` 和 `validate-admin.sh`。
若要把体积治理升级为阻断式预算，需要单独评估阈值、代码分割、字体加载和缓存策略。

## Docker 开发环境

```bash
./scripts/validate-docker.sh
```

## Staging 部署后检查

```bash
./scripts/validate-staging-host.sh
```

说明：`validate-staging-host.sh` 需要在 staging 主机上的仓库目录执行。默认会推导上一级目录的 `.env`，也可以显式传入 `APP_DIR=/path/to/app` 或 `ENV_FILE=/path/to/.env`。
