# 技术债与后续工作

这个文件承接当前任务范围外、但已经被确认真实存在的问题。它不是愿望清单，也不是路线图替代品；只记录需要跨会话、跨 agent 保留下来的工程债、验证缺口和后续治理项。

## 记录规则

- 只记录已经有证据的问题，不记录猜测。
- 不记录真实密钥、生产数据、用户隐私或漏洞利用细节。
- 每条事项应包含影响、当前证据、下一步和建议验证命令。
- 能在当前任务范围内安全修掉的问题优先修掉，不应把小修小补都堆到这里。
- 涉及数据库 schema、鉴权、AI 核心链路、依赖、Docker、CI/CD 或发布流程的事项，应先有方案或 ADR，再单独 PR 推进。
- 完成事项后不要直接删除历史，先在对应 PR 或提交总结里说明验证结果，再由维护者清理或归档。
