# 发布检查清单

这份清单用于 release、staging promotion 或重要合并前的人工 gate。当前项目还没有正式稳定版本；虽然仓库已有 production release / deploy workflows，发布前仍应按本文件确认版本、验证、风险和回滚路径。

## 适用场景

- 从 `develop` 准备发布或推广到 staging / production。
- 合并影响部署、Docker、CI、环境变量或外部 provider 的 PR。
- 发布包含用户可见能力、安全修复或数据库相关变更的版本。

## 发布前

- [ ] 当前分支、目标分支和 commit 范围明确。
- [ ] PR 描述完整：背景、主要改动、测试、风险、回滚方案。
- [ ] `CHANGELOG.md` 已记录用户可见变更、安全修复和破坏性变更。
- [ ] 版本号、tag 和 release notes 按 `docs/版本发布策略.md` 准备。
- [ ] `README.md`、`CONTRIBUTING.md`、`docs/验证清单.md` 与实际命令一致。
- [ ] `.env.example` 包含新配置项，且未包含真实密钥。
- [ ] `SECURITY.md` 中的报告和响应方式仍有效。
- [ ] 如果使用 AI agent，PR 中已记录 agent 负责范围、人工复核点和未验证项。

## 必跑验证

按改动范围运行：

- [ ] `git diff --check`
- [ ] `./scripts/validate-backend.sh`
- [ ] `./scripts/validate-web.sh`
- [ ] `./scripts/validate-admin.sh`
- [ ] `./scripts/validate-docker.sh`
- [ ] 跨模块或发布前：`./scripts/check.sh`

验证无法运行时，发布说明必须写明命令、失败原因和剩余风险。

## 风险检查

- [ ] 没有提交 `.env`、token、provider key、私钥、真实生产配置或敏感日志。
- [ ] 鉴权、权限、`UserContext`、Sa-Token 路由变更已单独说明风险。
- [ ] 数据库 schema、迁移、种子数据或 `vocata_*` 表结构变更已单独方案评审。
- [ ] WebSocket streaming、STT -> LLM -> TTS 链路和 AI provider 接线已做专项回归。
- [ ] API 响应契约和前端 ID 精度处理没有破坏兼容性。
- [ ] Docker、CI/CD、环境变量变更已有回滚路径。

## 发布后

- [ ] staging 或目标环境健康检查通过。
- [ ] 核查用户端、管理端和 API 入口可访问。
- [ ] 查看后端、用户端、管理端容器日志是否有新错误。
- [ ] 如果发布失败，按 `docs/部署环境说明.md` 的回滚路径恢复。
- [ ] 将已知遗留问题记录到 issue、PR 总结或 `docs/开源成熟度路线图.md`。
