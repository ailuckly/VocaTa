# 开发环境说明

这份文档是本地启动的单一入口。环境变量、启动顺序和 provider 选择都以这里为准；`docs/Docker开发环境.md` 只保留 Docker 编排约定。

## 启动入口

- 根目录 `.env`
- 根目录 `.env.example`
- 根目录 `.java-version`
- 根目录 `.nvmrc`
- `docker-compose.yml`
- `vocata-server/src/main/resources/application.yml`
- `vocata-web/package.json`
- `vocata-admin/package.json`

启动前可以先运行只读体检：

```bash
./scripts/doctor.sh
```

这个脚本只检查本机开发环境、关键文件和 `.env` / `.env.example` 的变量名一致性，不会安装
依赖、启动服务、修改 `.env` 或打印任何变量值。

如果使用 nvm，可以在仓库根目录执行 `nvm use` 切到 `.nvmrc` 指定的推荐 Node 版本。项目实际
支持范围仍以 `vocata-web/package.json`、`vocata-admin/package.json` 和
`scripts/check-node-version.sh` 为准。

Java 后端基线为 17，根目录 `.java-version` 用于 jenv/asdf 等工具识别推荐版本。`doctor.sh`
会读取这个文件，并在本机 Java 主版本和项目基线不一致时给出警告。

## 环境文件规则

第一次启动前复制模板：

```bash
cp .env.example .env
```

`.env` 是本地私有配置文件，可能包含真实第三方密钥，必须保持未跟踪状态。不要提交、截图或粘贴 `.env` 内容；如果密钥曾经外泄，应立即在对应平台轮换。

如果后续更新了 `.env.example`，运行 `./scripts/doctor.sh` 检查本地 `.env` 是否缺少新增变量或
保留了已废弃变量。脚本只报告变量名，不会输出密钥值。

## 核心栈启动必需配置

这些配置用于拉起本地开发的基础容器和基础联调：

- PostgreSQL：`POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD`、`DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USERNAME`、`DB_PASSWORD`
- PostgreSQL Docker 内部连接：`DOCKER_DB_HOST`、`DOCKER_DB_PORT`
- Redis：`REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD`、`REDIS_DATABASE`
- Redis Docker 内部连接：`DOCKER_REDIS_HOST`、`DOCKER_REDIS_PORT`
- Docker 端口映射：`POSTGRES_PORT`、`REDIS_EXPOSE_PORT`、`SERVER_PORT`、`WEB_PORT`、`ADMIN_PORT`
- 后端 profile：`SPRING_PROFILES_ACTIVE`
- 前端构建注入：`VITE_APP_URL`、`WEB_BUILD_MODE`、`ADMIN_BUILD_MODE`

## 需要功能配置的场景

这些配置只在你要使用对应功能时需要补齐；不要把它们和核心栈启动混为一谈。

- AI/对话默认 provider：`AI_LLM_PROVIDER`、`AI_STT_PROVIDER`、`AI_TTS_PROVIDER`
- 七牛对象存储：`QINIU_ACCESS_KEY`、`QINIU_SECRET_KEY`、`QINIU_BUCKET`、`QINIU_DOMAIN`、`QINIU_REGION`、`QINIU_KEY_PREFIX`
- 七牛 AI/STT：`QINIU_AI_API_KEY`、`QINIU_AI_BASE_URL`、`QINIU_AI_MODEL`、`QINIU_AI_TIMEOUT`、`QINIU_STT_ENDPOINT`、`QINIU_STT_MODEL`
- 科大讯飞 TTS：`XUNFEI_TTS_APP_ID`、`XUNFEI_TTS_API_KEY`、`XUNFEI_TTS_SECRET_KEY`
- 邮件：`MAIL_USERNAME`、`MAIL_PASSWORD`
- Gemini：`GEMINI_API_KEY`、`GEMINI_BASE_URL`、`GEMINI_MODEL`、`GEMINI_TIMEOUT`
- OpenAI：`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`、`OPENAI_TIMEOUT`
- SiliconFlow：`SILICONFLOW_API_KEY`、`SILICONFLOW_BASE_URL`、`SILICONFLOW_AI_MODEL`、`SILICONFLOW_TIMEOUT`
- 可选工具：`PGADMIN_DEFAULT_EMAIL`、`PGADMIN_DEFAULT_PASSWORD`

说明：

- 当前代码里 AI provider 默认仍是 `qiniu/qiniu/xunfei`，所以如果你要把完整后端功能都跑起来，对应的第三方配置仍然要准备好。
- 文件上传、AI 调用和语音相关功能依赖各自的 provider 配置；如果只是看数据库、Redis 或前端静态页面，不一定需要把所有第三方账号都补全。

## 推荐启动模式：宿主机开发

这个模式用于日常开发。PostgreSQL / Redis 由 Docker 提供，后端和前端在宿主机运行，支持热更新。

1. 准备 `.env`。
2. 确认 `.env` 中宿主机连接配置为 `DB_HOST=localhost`、`DB_PORT=${POSTGRES_PORT}`、`REDIS_HOST=localhost`、`REDIS_PORT=${REDIS_EXPOSE_PORT}`。
3. 启动基础依赖：

```bash
docker compose up -d postgres redis
```

4. 导入后端环境变量并启动后端：

```bash
set -a
source .env
set +a
cd vocata-server
mvn spring-boot:run
```

如本机 Maven 仓库不可写，可使用：

```bash
cd vocata-server
mvn -Dmaven.repo.local=/tmp/juhao_m2repo spring-boot:run
```

5. 启动用户端和管理端：

- 用户端：`cd vocata-web && npm run dev`
- 管理端：`cd vocata-admin && npm run dev`

访问入口：

- 用户端：`http://localhost:3000`
- 管理端：`http://localhost:3001`
- 后端健康检查：`http://localhost:9009/api/health`

## 可选启动模式：全量 Docker

这个模式用于验证容器构建和近似发布态静态前端，不提供前端热更新。

1. 准备 `.env`。
2. 确认 Docker 内部连接配置为 `DOCKER_DB_HOST=postgres`、`DOCKER_DB_PORT=5432`、`DOCKER_REDIS_HOST=redis`、`DOCKER_REDIS_PORT=6379`。
3. 启动：

```bash
docker compose up -d --build
```

全量 Docker 模式下，前端容器会执行 `npm run build:${WEB_BUILD_MODE}` 和 `npm run build:${ADMIN_BUILD_MODE}`。当前支持 `development`、`local`、`test`、`prod`、`production`。

需要数据库管理或邮件调试时，再启用 tools profile：

```bash
docker compose --profile tools up -d
```

## 数据库初始化状态

当前仓库还没有正式 schema migration 体系，也没有可从空库完整恢复业务表结构和种子数据的脚本。新建空库后，服务可能能启动，但涉及业务表的接口可能失败。

当前建议：

- 日常开发使用已有开发库或从可信备份恢复。
- 不要把本地数据库 dump、真实用户数据或生产数据提交到仓库。
- 后续规范化应补 Flyway/Liquibase 或独立 SQL 初始化脚本，并在 CI 中增加空库启动校验。

## 常见问题

- 端口冲突：核心栈默认会占用 `55433`、`6380`、`9009`、`3000`、`3001`，冲突时优先改 `.env`，不要改容器内端口。
- tools profile 端口：`5050`、`1025`、`8025` 只会在执行 `docker compose --profile tools up -d` 时占用。
- `.env` 没同步：`docker-compose.yml` 读取的是根目录 `.env`，改完模板后要同步到实际文件。
- 后端本机启动连不上数据库：确认已经 `source .env`，并确认 `DB_HOST/DB_PORT` 指向宿主机暴露端口。
- 全量 Docker 后端连不上数据库：确认 `DOCKER_DB_HOST/DOCKER_DB_PORT` 和 `DOCKER_REDIS_HOST/DOCKER_REDIS_PORT` 指向 compose 内部服务。
- 完整后端起不来：先看数据库/Redis 连接，再看 AI、七牛和语音相关配置，最后看 `docker compose logs vocata-server`。
- 前端请求地址不对：`VITE_APP_URL` 是构建期变量，改了以后需要重新构建前端容器。
- 数据库数据不一致：当前开发数据库使用 `pgvector/pgvector:pg17`，恢复旧卷或备份前先确认版本和扩展兼容。
- 邮件不通：只有在你要验证邮箱相关功能时，才需要检查 `MAIL_USERNAME` 和 `MAIL_PASSWORD`。
