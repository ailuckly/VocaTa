# AI 审查清单

这份清单用于 AI coding agent 做代码审查、PR 自查或实现后的风险复核。它补充
`docs/AI协作流程.md`，重点不是格式，而是防止安全、正确性和验证证据被漏掉。

## 审查顺序

1. 先确认分支、工作区状态和改动范围。
2. 先看高风险路径，再看一般可维护性。
3. 先列问题，再列总结；没有问题时也要说明测试缺口和剩余风险。
4. 每个问题都必须有文件位置、影响说明和修复方向。
5. 不把风格偏好当成主要问题，除非它会影响可维护性或项目规范。

## 高风险路径

优先检查以下区域：

- 鉴权、Sa-Token 路由、`UserContext`、管理员权限。
- 数据写入、删除、事务、幂等性和并发。
- API 响应契约、前端 ID 字符串精度处理、分页结构。
- `AiChatWebSocketHandler`、WebSocket streaming、STT -> LLM -> TTS 链路。
- 第三方 AI provider 接线、超时、重试、错误输出和密钥处理。
- Docker、CI/CD、部署、回滚、环境变量。
- 依赖新增、删除或升级。

## 审查输出格式

建议使用以下结构：

```text
Findings
- [P1] 标题
  文件：path/to/file:line
  影响：
  原因：
  修复方向：

Open Questions / Assumptions
-

Test Gaps
-

Brief Summary
-
```

优先级建议：

- `P0`：会导致数据泄露、权限绕过、生产不可用或严重数据损坏。
- `P1`：高概率用户可见错误、核心链路回归、重要安全风险。
- `P2`：边界条件、可靠性、兼容性或测试缺口。
- `P3`：小型维护性问题或文档不一致。

## 必查问题

- 是否有真实密钥、token、私钥、生产配置或敏感日志进入提交。
- 是否改变了公开 API、路由、响应结构或错误码。
- 是否改变了数据库表结构、字段语义或实体映射。
- 是否改变了流式对话、语音打断、provider 选择或模型配置。
- 是否新增了没有必要的依赖或工具链。
- 是否有测试能够证明新增行为或 bugfix。
- 是否记录了未验证项、失败命令和剩余风险；确认出的范围外技术债应写入 `docs/技术债与后续工作.md`。
