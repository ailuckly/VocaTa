# 维护与分流指南

这份指南用于 issue triage、PR review 排队、AI agent 任务分配和维护者日常决策。它不改变
GitHub 自动化行为，只把当前仓库的人工维护规则写清楚。

## Triage 节奏

- 新 issue 先确认类型：bug、feature、question、AI agent task、security。
- 安全问题不在公开 issue 讨论，按 `SECURITY.md` 处理。
- Bug 先看能否复现，再判断影响范围和优先级。
- Feature 先看用户问题是否明确，再判断是否需要 ADR 或拆分。
- AI agent task 先确认目标、范围、高风险边界和验证计划是否完整。

## 推荐标签

当前不强制预创建标签，但建议按以下语义使用：

| 标签 | 用途 |
| --- | --- |
| `bug` | 可复现缺陷 |
| `enhancement` | 功能或体验改进 |
| `question` | 使用、环境、流程问题 |
| `documentation` | README、docs、注释或模板 |
| `security` | 安全相关公开跟踪项；漏洞细节仍走私下渠道 |
| `ai-agent` | AI agent 可执行或已参与的任务 |
| `backend` | `vocata-server/` |
| `web` | `vocata-web/` |
| `admin` | `vocata-admin/` |
| `ci` | `.github/`、CI/CD、验证脚本 |
| `docker` | Docker、compose、环境变量 |
| `needs-repro` | 需要复现信息 |
| `needs-decision` | 需要维护者决策或 ADR |
| `blocked` | 等待外部条件或人工确认 |

## 优先级

- `P0`：安全漏洞、生产不可用、数据损坏、鉴权绕过。
- `P1`：核心用户路径不可用、登录/会话/实时对话明显回归。
- `P2`：重要边界问题、兼容性问题、可靠性或测试缺口。
- `P3`：文档、维护性、小型体验或低风险清理。

## AI Agent 分配规则

适合交给 AI agent：

- 文档补齐、模板整理、测试补强。
- 单模块 bugfix，且复现路径明确。
- 非高风险代码审查、重构计划、验证脚本整理。

需要维护者先确认：

- 鉴权、数据库 schema、WebSocket streaming、AI provider 接线。
- Docker、CI/CD、部署、release、回滚策略。
- 新增、移除或升级依赖。
- 跨 backend / web / admin 的联动改动。

## 关闭规则

可以关闭 issue 的情况：

- 已通过 PR 修复，并记录验证结果。
- 无法复现且长时间缺少必要信息。
- 与当前产品方向不一致，且维护者说明原因。
- 安全问题已转入私下处理渠道。

关闭时尽量留下下一步入口：相关 PR、文档、验证命令、替代方案或后续 issue。

## 技术债承接

确认真实存在但不适合当前任务直接修复的问题，应记录到 `docs/技术债与后续工作.md`。记录时保留证据、影响、下一步和建议验证命令；不要把真实密钥、生产数据、用户隐私或漏洞利用细节写入公开文档。
