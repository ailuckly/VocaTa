# 依赖与安全自动化方案

本方案用于后续单独 PR 引入 Dependabot、CodeQL、gitleaks 配置和 CODEOWNERS。当前文件
只定义实施路径，不新增 `.github/dependabot.yml`、CodeQL workflow、`.gitleaks.toml`
或 `CODEOWNERS`。

关联 ADR：`docs/adr/0002-dependency-and-security-automation.md`

## 当前状态

- CI 已有 PR 级 gitleaks 扫描，扫描范围是 `origin/${BASE_REF}..HEAD`。
- CI 已有 backend / web / admin 路径过滤和验证脚本。
- 后端依赖在 `vocata-server/pom.xml`。
- 用户端 npm 依赖在 `vocata-web/package.json` 和 `vocata-web/package-lock.json`。
- 管理端 npm 依赖在 `vocata-admin/package.json` 和 `vocata-admin/package-lock.json`。
- GitHub Actions 依赖分布在 `.github/workflows/*.yml`。
- 当前没有 `.github/dependabot.yml`、CodeQL workflow、`.gitleaks.toml` 或 `CODEOWNERS`。

## 目标

在不制造过多维护噪音的前提下，让依赖更新、安全扫描和 review 路由逐步接近成熟开源
项目的标准。

## Phase 1: Dependabot

Outcome:

- 定期检查 GitHub Actions、Maven、用户端 npm 和管理端 npm 依赖。
- PR 数量受控，默认合入 `develop`。

Recommended config:

- `github-actions` at `/`
- `maven` at `/vocata-server`
- `npm` at `/vocata-web`
- `npm` at `/vocata-admin`
- schedule: weekly
- open pull requests limit: low, such as 3 per ecosystem
- labels: `dependencies`, plus `backend` / `web` / `admin` / `ci` when useful

Acceptance checks:

- `.github/dependabot.yml` parses.
- Dependabot PRs target `develop`.
- Package lock updates are included for npm PRs.
- PR template asks for validation and risk notes.
- No runtime dependency is upgraded without module-specific validation.

## Phase 2: CodeQL

Outcome:

- Java and JavaScript/TypeScript static analysis runs on PRs and pushes to protected branches.

Recommended scope:

- languages: `java`, `javascript-typescript`
- trigger: PR and push to `develop` / `master`
- schedule: weekly
- avoid blocking normal docs-only PRs until false-positive behavior is understood

Acceptance checks:

- Workflow has least-needed permissions.
- Runtime impact is measured in the first few runs.
- False positives are tracked in issues or PR notes.
- Findings touching auth, data writes, WebSocket, provider wiring, or secrets are triaged as
  high priority.

## Phase 3: gitleaks Config

Outcome:

- Project-specific secret scanning rules and allowlists are versioned.

Rules:

- Do not add broad allowlists for `.env`, tokens, provider keys, private keys, or production
  config.
- Prefer narrow allowlists for known placeholder strings and test fixtures.
- Keep redaction enabled in CI.
- Continue scanning only PR-introduced changes unless a separate historical scan is planned.

Acceptance checks:

- `.gitleaks.toml` is validated by a local gitleaks run.
- Existing secret scan behavior is not weakened.
- Placeholder env examples remain allowed only when they do not contain real values.

## Phase 4: CODEOWNERS

Outcome:

- Review requests route to stable maintainers or teams.

Do not add until:

- there is a real GitHub username or team to own each area
- `MAINTAINERS.md` review ownership is stable
- the maintainer accepts auto-review noise

Candidate ownership areas:

- `/vocata-server/`
- `/vocata-web/`
- `/vocata-admin/`
- `/.github/`
- `/scripts/`
- `/docs/`
- `/.ai-rules/`

Acceptance checks:

- CODEOWNERS syntax is valid.
- Owner handles exist in the GitHub repository.
- Review requests match `MAINTAINERS.md` ownership.

## Rollout Order

1. Add Dependabot.
2. Observe PR volume for at least one update cycle.
3. Add CodeQL.
4. Add `.gitleaks.toml` only after concrete custom rules are needed.
5. Add CODEOWNERS only after owner/team names are stable.

## Validation Matrix

| Change | Validation |
| --- | --- |
| Dependabot | YAML parse, first generated PR review, module-specific validate script |
| CodeQL | workflow parse, first analysis result, false-positive triage |
| gitleaks config | `gitleaks detect --redact --no-banner`, existing CI secret scan |
| CODEOWNERS | syntax check, owner existence, PR review request behavior |

## Known Risks

| Risk | Mitigation |
| --- | --- |
| Dependabot PR noise | weekly schedule, low open PR limit, ecosystem-specific labels |
| Breaking dependency upgrades | require validation script for touched module |
| CodeQL false positives | track findings and tune only after evidence |
| gitleaks allowlist too broad | require narrow allowlist entries and review |
| CODEOWNERS review friction | delay until ownership is stable |
